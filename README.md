# HearHere

A Chrome extension (Manifest V3) that reads text on any web page out loud. You can use your OS voices for free, or premium voices from **OpenAI** or **ElevenLabs** with your own API key.

## Features

- **Select → Read:** highlight text and a **🔊 Read** button appears next to it.
- **Hover Read:** turn it on, then rest your cursor on a paragraph. It gets highlighted and read aloud.
- **Playback controls:** an on-page player bar and the toolbar popup both have play/pause, stop and speed (0.75× to 2×).
- **Keyboard shortcuts** (change them at `chrome://extensions/shortcuts`):

  | Action | Default |
  |---|---|
  | Read selection (or the paragraph under the cursor) | `Alt+Shift+R` (`⌥⇧R` on Mac) |
  | Pause / resume (starts reading if nothing is playing) | `Alt+Shift+Space` |
  | Stop | `Alt+Shift+S` or `Esc` |
  | Toggle Hover Read | `Alt+Shift+H` |

- Right-click selected text and choose **Read aloud with HearHere**.

## Voice engines

| Engine | Cost | Setup |
|---|---|---|
| System voice | Free | None. Uses your OS voices through `chrome.tts`. |
| OpenAI | Your OpenAI usage | Paste an API key in **Settings**, then pick a model (`gpt-4o-mini-tts` / `tts-1` / `tts-1-hd`), a voice and an optional speaking style. |
| ElevenLabs | Your ElevenLabs credits | Paste an API key (with *Text to Speech* and *Voices: read* access). Your voices load automatically, and ▶ previews them for free. |

To get there, click **Voice settings** in the popup, or right-click the toolbar icon and choose **Options**.

### How it keeps your API bill down

- **Lazy generation:** audio is generated one sentence ahead of what's playing, never the whole text up front. Stopping halfway means you only pay for what you heard plus one sentence.
- **Speed is free:** audio is always generated at 1× and sped up or slowed down in the browser with pitch kept. Changing speed never makes a new request.
- **Local cache:** generated audio is cached in IndexedDB (up to ~150 MB, oldest removed first), so replaying the same text costs nothing.
- **Daily character limit** (default 20,000): when it's reached, HearHere switches to the free system voice.
- **Confirm long reads:** it asks before reading more than 3,000 characters at once with a paid voice.
- **Hover Read guards:** with a paid voice, the cursor has to rest for 1 second (system voice: 0.45 s), and blocks over 1,500 characters are skipped. Select those to read them.
- **Usage meter:** characters today and this month, per provider, in Settings and in the popup.
- **Graceful fallback:** an invalid key, no credits or a network failure shows a toast and continues with the system voice.

All of these thresholds can be changed in Settings.

### About your keys

Keys are stored only on this computer (`chrome.storage.local`, not synced) and sent only to the provider's API from the extension, never to the pages you visit. They're stored unencrypted, like in any extension, so use a key you can revoke and set a spending limit in the provider's dashboard.

## Install (developer mode)

1. Open `chrome://extensions` and turn on **Developer mode**.
2. Click **Load unpacked** and pick this folder.
3. The settings page opens on first install. After editing the code, click ↻ on the HearHere card.

## Architecture

```
manifest.json
src/background.js     reading session + engine routing (system ↔ cloud), usage tracking, shortcuts, context menu
src/content.js        selection button, Hover Read, highlights, player bar, cost-guard confirm (Shadow DOM)
src/content.css       highlight styles injected into pages
src/providers.js      OpenAI + ElevenLabs API clients (shared)
src/cache.js          IndexedDB audio cache (shared)
offscreen/            offscreen document that fetches, caches and plays cloud audio
options/              settings page: keys, voices, models, cost guards, usage
popup/                toolbar popup: controls, speed, Hover Read, engine switch, usage
icons/                generated by scripts/make_icons.py
```

How a reading flows: the content script sends the text to the background worker. The worker cleans it (strips `[12]` citation marks and URLs) and splits it into chunks (~220 characters for the system voice, ~400 for cloud voices). Cloud chunks go to the offscreen player, which fetches chunk *n* while *n‑1* plays, caches each clip and reports usage back. Speed changes set `playbackRate` directly.

## Known limitations

- It doesn't work on `chrome://` pages, the Chrome Web Store or the built-in PDF viewer.
- It only runs in the top frame (no iframes).
- The first sentence with a cloud voice takes roughly 0.3–1 s to start, while it's generated.
